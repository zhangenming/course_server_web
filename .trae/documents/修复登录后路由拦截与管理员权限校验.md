## 问题诊断
- 当前并未使用 `vue-router`，入口逻辑在 `src/main.ts:22` 通过 `location.search === '?admin'` 判断是否挂载后台界面，这很脆弱：仅当 URL 完全等于 `?admin` 才生效，其他查询参数或路径均失效。
- 未做服务端角色校验，任何拥有 token 的用户只要拼接 `?admin` 就能看到后台 UI；只有在发起接口时遇到 401 才会被 `apiFetch` 重载到登录页，属于事后拦截。
- 结果就是“路由拦截进入其他界面没有生效”。入口没有从用户角色源头拦截，且对 Admin 的切换逻辑过于简化。

## 修复方案（不引入路由库）
1. 强化入口判断：
   - 解析 URL：`wantsAdmin = URLSearchParams(location.search).has('admin') || location.pathname.startsWith('/admin')`，同时允许路径型 `/admin`。
   - 读取用户信息：登录后统一调用 `api/v1/users/me` 获取角色；`isAdminUser = user.role === 'admin'`。
   - 仅当 `wantsAdmin && isAdminUser` 才挂载 `Admin`，否则挂载 `App`。
2. 纠正非法 URL：
   - 当用户非管理员但访问了 `?admin` 或 `/admin`，用 `history.replaceState` 去掉该标记并回到根路径，避免刷新后继续进入后台视图。
3. 一致的 401 行为：
   - 保持 `src/utils/request.ts:69-79` 的 401 处理逻辑；后续可将 `location.reload()` 优化为回到登录路径（若引入路由再切换为 `router.replace('/login')`）。

## 可选增强（引入 vue-router，推荐）
1. 安装 `vue-router@4`，定义路由：`/login`、`/`（前台）、`/admin`（后台）。
2. 在路由 `beforeEach` 中做统一拦截：
   - 无 token → 重定向 `/login`。
   - 访问 `/admin` 且角色非管理员 → 重定向 `/`。
3. 迁移入口：`main.ts` 改为创建路由与应用实例，不再手动用 `createApp(Admin/App/Login)` 切换。
4. 将 `apiFetch` 的 401 跳转改为 `router.replace('/login')`，与路由守卫行为一致。

## 具体改动点（不引入路由库的版本）
- `src/main.ts:22`：将 `const isAdmin = location.search === '?admin'` 改为解析查询与路径的 `wantsAdmin`。
- `src/main.ts`：登录后统一调用 `api/v1/users/me`，通过返回的 `role` 决定是否可进入后台；对非法管理员访问清理 URL 并挂载前台。
- 保留 `document.body.classList` 的 Admin 样式切换逻辑，基于最终判断结果。
